## Outcome

Recover GitHub API-backed discovery and the single-job export/deployment so the
Pages artifact uses the HTML generated by that run. Both PHP HTTP transports
verify certificates and host names. Authenticated requests are restricted to
HTTPS api.github.com on its default port and never follow redirects. Non-2xx,
TLS, malformed JSON and network failures return failure without retrying through
a different transport.

Only directories containing a Git marker count as local repositories. Without
local repositories, API failure aborts export before replacing prior HTML/cache.
A successful empty repository list remains a valid result. Export refreshes the
cache without deleting its previous contents before the API request succeeds.

Pull requests run PHP lint, transport regressions and full offline export tests.
Pages deployment runs after validation on main/schedule/manual triggers and
uploads only staged index.html plus an existing CNAME, not PHP/scripts/cache.
The workflow stages only its generated HTML in the automatic commit.

## Validation

The original recovered transport fails the certificate-verification regression.
Both mocked transports now pass successful/error status, redirect, disallowed
host/scheme/port/credential URL, malformed JSON and transport-failure cases.
Three complete exporter tests pass with the HTTP boundary replaced by fixtures:
correct API projects despite docs/tests directories, preserved files on API
failure, and valid empty repository lists. PHP lint and git diff --check pass.
No domain configuration or host cron was executed during validation.
